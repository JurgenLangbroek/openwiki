# Fork-local behavior attaches at seams, never by replacing upstream symbols

This fork carries roughly 7k lines of Glean and Brain Wiki machinery on top of a fast-moving upstream — 85 commits in the 12 days before the 2026-07 sync — and takes upstream as plain merge commits so future syncs stay clean. A trial merge showed that 16 of 30 conflicts existed only because the fork had _replaced_ upstream symbols in place: Connector Posture overwrote `supportsAgenticDiscovery` in all seven connector sources (right where upstream then added `mode`), and `getOpenWikiHomeDir()` replaced the `openWikiHomeDir` constant that every upstream home-path importer uses. Fork-local behavior therefore attaches at seams that leave upstream identifiers intact: per-connector fork attributes live in fork-owned side tables keyed by `ConnectorId`; `OPENWIKI_HOME` support keeps upstream's exported constant names and leans on ESM live bindings (`export let`) for test-time re-resolution; connector-specific wizard logic lives in `sources/<connector>/setup.ts`, which is upstream's own convention, so `credentials.tsx` gains only an import and an option entry.

**Considered options:** accessor functions for the home paths were the original choice and did buy simpler tests, at the cost of conflicting with every upstream file that imports a home path — including files that did not exist yet, such as upstream's `telemetry/config.ts`. Cherry-picking a curated subset of upstream rather than merging was rejected because it rewrites upstream SHAs and leaves `main..upstream/main` permanently dirty, re-presenting every skipped commit as a conflict forever.

**Consequences:** `export let` for a path constant is unusual and needs a comment saying why it exists. Module-level constants _derived_ from it in other modules still snapshot at import time — correct for a short-lived CLI where `OPENWIKI_HOME` is fixed before launch, but tests that mutate the home mid-process must call `resetOpenWikiHomePaths()`. The side table is resolved once at the connector registry boundary and stamped onto the runtime, so consumers and test fakes still treat posture as a value rather than performing lookups; the table is exhaustive by type, so a new connector cannot be added without declaring its posture.
